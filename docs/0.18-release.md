# 0.18.0 release checklist

Tag main after this pull request lands, and only on jow's go. Nobody tags or deploys before that.

## What changes for people and agents

- **Coordination:** task claims and `kiwi answering N` are compare-and-set on the relay, so racing agents can't both take one (#333). `kiwi lock` / `kiwi unlock` hold a lease with a line behind it (#339). Notes, claims, leases and reactions leave the conversation (#341).
- **No more coordinator-only mode:** the coordinator role is an optional lead, and anyone talks to people directly (#338).
- **What wakes an agent:** #general, its rooms and task threads, and @mentions; the rest is read with `kiwi log --task T7` / `--room R` (#349). An answer posted in a task's thread now reaches whoever asked there.
- **CLI:** `kiwi send --to WHERE` is the one way to say where a message goes (#362). Handles are adjective-animal (#353). A task title over 200 characters is refused (#335).
- **App:** a slash in the composer runs commands (#354), and `/compact` folds the history behind a summary jow approves (#357). An agent's question lives in the composer with clickable options (#348). Task cards, room chips, proof links and closing digests (#334, #343, #344, #345, #346). The microphone says why dictation can't run (#350).
- **GitHub:** the Kiwi GitHub App's webhooks reach a channel (#351, #356). A PR shows its real state and checks on its task (#358, #359), and a PR on a `T<n>-…` branch links back to its task (#365). Diffs and the `kiwi/review` check (#361, #363). A person links their GitHub account from the desktop app (T41, #360). Setup and how it works: `docs/github-app.md`.
- **Wire:** new events (leases, compact, GitHub news) and relay slots. Clients older than 0.18.0 drop the new events as malformed, so update every machine. Snapshots move to a new version: old ones are ignored and the first fold reads the log.
- **Daemon protocol:** unchanged from 0.17.0.
- **Not in 0.18.0:** GitHub issues ↔ tasks (T453) and `--re` threads as inline quotes in the app (T430) come in 0.19.

## Relay deploy

- **New secrets the relay reads:** `GITHUB_WEBHOOK_SECRET`, `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, and the public `GITHUB_APP_CLIENT_ID`. The owner setup below sets them. Without them the relay still runs; the GitHub parts stay off.
- **Wrangler migration `v8`** adds the `Repos` Durable Object (`REPOS` binding) that routes a repo's webhooks to its channels. `wrangler deploy` (the `deploy-relay` job, or `bun run relay:deploy`) applies it; nothing to do by hand.
- The app's first-load bundle budget is now 791,000 bytes (CI's `build / bundles`).

## Owner setup (jow)

Do these in order. Values to paste are in code blocks; names are exactly what the code reads.

1. **GitHub App and webhook secret** (#382). Make the secret and keep it:
   ```
   openssl rand -hex 32
   ```
   Create the App at https://github.com/settings/apps/new: name `Kiwi Channels`, homepage `https://channels.kiwiinit.com`, webhook Active with URL `https://channels.kiwiinit.com/v1/github/webhook` and the secret above. Repository permissions read-only: Actions, Checks, Contents, Metadata, Pull requests. Events: Check run, Pull request, Push, Workflow run. Install on only this account. Then store the secret on the relay, from the repo folder:
   ```
   bunx wrangler secret put GITHUB_WEBHOOK_SECRET
   ```
   App page → Install App → your repos. In the app: channel → Details → Repos → add `kiwi-init/channels` → Save.
2. **App permissions and key** (#417). On the App's page copy the App ID, then Private keys → Generate a private key (a `.pem` downloads). Permissions & events: set Checks, Pull requests and Issues to Read and write, and subscribe to Issues; Save. Accept the new permissions at https://github.com/settings/installations → Kiwi Channels → Configure → Review request. Store both on the relay:
   ```
   bunx wrangler secret put GITHUB_APP_ID
   ```
   ```
   bunx wrangler secret put GITHUB_APP_PRIVATE_KEY < ~/Downloads/YOUR-FILE.private-key.pem
   ```
   Only after both succeed, delete the `.pem` download.
3. **Linking a GitHub account (T41)**. In the App's settings, under Identifying and authorizing users: tick **Enable Device Flow**, untick **Expire user authorization tokens**, Account permissions none. Give the relay the App's public Client ID (from the App's page). The Worker reads it from its environment, so either store it like the others:
   ```
   bunx wrangler secret put GITHUB_APP_CLIENT_ID
   ```
   or commit it under `vars` in `wrangler.jsonc`, as `docs/github-app.md` says (a Bun relay: `GITHUB_APP_CLIENT_ID=… kiwi relay`). It is public: nothing secret here. After the deploy, Settings → GitHub → Link GitHub shows a code for github.com/login/device. Full text: `docs/github-app.md`.
4. **WorkOS "Continue with GitHub"** (#419). Production already offers it. Test once: desktop app → Create channel → Continue with GitHub → authorize. If it says *redirect_uri is not associated*, set the Callback URL of the GitHub App production uses to exactly:
   ```
   https://auth.workos.com/sso/oauth/github/v2NKNq81gZ0cFylXa5QU3O4Iz/callback
   ```

## Order

1. Land this pull request (version 0.18.0, CHANGELOG, site download names, this checklist) after T41, T45 and T72 have landed.
2. If anything else landed on main after it, run `bun run changelog --write` on main, check each new entry against what its PR finally did, and commit.
3. Rehearse on main's commit: `gh workflow run ci.yml --ref main`, then wait for `ci-ok`. Its `release / rehearsal` job runs the tag's build without publishing, and only this manual run signs and notarizes the macOS app. Don't tag until it passes; it prints the tag to push.
4. On jow's go, tag `v0.18.0` on main's commit and push the tag. Wait until the GitHub release has the CLI binaries, the dmgs, the zips, the AppImage and the deb.
5. Watch the `deploy-relay` job after `publish`. The relay must be deployed for claims, leases and the GitHub webhooks. If it fails, re-run it, or deploy by hand with `bun run relay:deploy`.
6. Do the owner setup above if not done yet; the webhooks and diffs need the relay deployed first.
7. Update the CLI (`curl …/install | sh`) and the Channels app on each machine.
8. Start a new session for each agent: the new brief (`--to`, leases, `kiwi answering`, what wakes you) reaches an agent only through a new session or a new `kiwi join`.

## Do not

- Do not tag or deploy before jow says go.
- Do not deploy the Worker by hand before the GitHub release exists: the site's download links name `Channels-0.18.0-…` and would 404.
- Do not tag a branch. If main has moved since this landed, rewrite the changelog on main (step 2), rehearse (step 3) and tag main.
