# 스펙과 작업

사람이 요청합니다. 에이전트는 그 사람과 함께 요청을 **스펙**으로 적습니다. 사람이 스펙을 승인하면, 처음으로 손이 빈 에이전트가 시작합니다. 스펙 안의 일은 에이전트가 결정하고, 스펙 밖의 일은 사람에게 묻습니다.

<!-- figure: spec -->

## 스펙

사람의 메시지에 대한 스펙은 마크다운입니다. 이유, 포함하는 것과 제외하는 것, 아직 열려 있는 질문, 그리고 완료를 증명하는 체크박스를 담습니다.

```markdown
# Export the board as CSV

## Done when
- [ ] The Tasks view has an Export button that saves `board.csv`
- [ ] Maya opens it in Numbers and the columns line up
```

- 리드나 다른 에이전트가 초안을 씁니다: `kiwi spec write 150 --file spec.md`.
- 누구나 스펙을 편집할 수 있고, 누구나 한 줄에 댓글을 달 수 있습니다. 앱에서는 단어를 선택하고, CLI에서는 `kiwi spec comment 150 "…" --on "the line"`을 씁니다. 댓글은 그 사람의 메시지 스레드에 답장으로 달리므로, 에이전트는 다른 스레드처럼 댓글을 읽습니다.

## 승인

사람이 자신이 읽은 버전을 승인합니다. 승인할 수 있는 사람은 요청한 사람, 소유자, 또는 소유자가 결정에 답할 수 있게 한 사람입니다. 에이전트는 절대 승인할 수 없습니다. 승인에는 그 버전이 명시되므로, 누군가 읽는 동안 이루어진 편집이 몰래 통과할 수 없습니다.

승인 후 체크박스를 체크하는 것은 진행 상황입니다: `kiwi spec tick 150 "columns line up"`. 그 밖의 편집은 변경으로, 사람에게 diff로 표시되며, 사람이 승인할 때까지 새 작업은 기다립니다. 이미 시작한 작업은 계속됩니다.

## 스스로 시작

스펙이 승인되면 다른 할 일이 없는 첫 에이전트가 맡습니다. [`kiwi loop`](loop.md)는 자리가 비어 있을 때 이를 맡고, 긴 세션에 있는 에이전트는 승인 알림에 깨어나 `kiwi spec start 150`을 실행합니다. 에이전트는 스펙을 작업으로 나누어 사람의 메시지 아래에 등록하고(`kiwi task add "…" --ask 150`), 손이 빈 에이전트가 열린 작업을 맡습니다.

**승인된 스펙에서만 작업**(소유자의 스위치로, 앱에서 만든 모든 채널에서 켜져 있음)이 켜져 있으면 모든 작업은 승인된 스펙의 한 단계입니다. GitHub 이슈도 같은 방식으로 작업이 됩니다: `kiwi task add --ask 150 --issue 12`.

## 단계

단계는 누구도 직접 입력하지 않습니다. 일어난 일에 따라 정해집니다.

| 단계 | 시점 |
| --- | --- |
| 초안 | 사람이 승인할 때까지 |
| 승인됨 | 대기열 순서와 함께 에이전트를 기다리는 중 |
| 진행 중 | 열린 작업이 있음 |
| 전달됨 | 모든 작업이 끝나고 모든 체크박스가 체크됨 |
| 수락됨 또는 철회됨 | 사람의 판정 |

사람은 메모와 함께 스펙을 **반려**할 수도 있습니다. 스펙은 다시 에이전트를 기다리고, 메모는 계획을 세우는 에이전트의 첫 지시가 됩니다. 철회하면 열린 작업은 보류됩니다.

## 작업

작업은 열림, 진행 중, 완료 순서로 진행됩니다.

```bash
kiwi task add "freeze protocol v1" --ask 150 --start   # file it and take it
kiwi task assign T3 win "edge detection works; multi-monitor next"
kiwi task checkpoint T3 --file note.md                 # where it stands, for the next session
kiwi task done T3
```

`kiwi task start`는 아무도 맡지 않은 작업만 맡습니다. 두 에이전트가 동시에 맡으려 하면 한쪽이 이기고, 다른 쪽은 누가 맡았는지 안내받습니다.

## 앱에서

**스펙** 화면에서 작업 전체를 봅니다. 맨 위에 지금 카드가 있고, 그 아래에 필요한 일(내 확인 필요, 진행 중, 에이전트 대기, 초안)별로 스펙이 나열되며, 각 스펙 아래에 열린 작업이 표시됩니다. 스펙을 열면 세 부분이 있습니다.

- **스펙**: 본문과, 인용한 줄 옆 여백에 달린 댓글.
- **내부**: 에이전트의 작업을 한눈에 봅니다. 작업마다 풀 리퀘스트가 있고, 모든 메시지를 한 번의 클릭으로 열 수 있습니다.
- **결과**: 완료 조건, 병합된 풀 리퀘스트, 시도한 것, 그리고 수락, 반려, 철회.
