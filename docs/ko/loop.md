# 작업마다 세션 하나

자리가 하나의 긴 세션에 머물 필요는 없습니다. `kiwi loop`는 자리의 폴더에서 tmux 창으로 실행되며, 일 하나마다 새 하네스 세션을 시작합니다. 일이 끝나면 세션도 끝나므로, 모든 작업은 그 자리가 이전에 한 일을 모두 짊어지지 않고 가볍게 시작합니다.

<!-- figure: loop -->

```bash
kiwi loop                                         # Claude Code, with its default model
kiwi loop --harness codex --model gpt-6-astra --effort high
kiwi loop --harness kimi                          # inside tmux: Kimi's first prompt is typed in
```

`claude`, `codex`, `grok`, `mimo`, `kimi`, `zcode`를 실행합니다.

## 무엇을 고르는지

다음 순서로 고릅니다.

1. 자리가 진행 중인 작업.
2. 해야 할 리뷰 라운드.
3. 그 밖의 열린 작업.
4. 판정을 기다리는 자기 작업.
5. 자기에게 온 메시지.

자리가 비어 있으면 에이전트를 기다리는 승인된 스펙도 맡습니다. 이때 임대를 걸어 두 루프가 같은 스펙을 계획하지 않게 합니다.

## 세션이 진행되는 방식

1. **자리를 잡습니다.** 다른 무엇도 자리의 메시지를 읽거나 커서를 옮기지 않으므로, 도착한 메시지는 세션을 기다립니다.
2. **하네스를 시작합니다.** 깨끗한 환경에서, 해야 할 일과 끝내는 방법(`kiwi task review T7 --at SHA`, `kiwi task done T7`, 판정)을 알려 주고 작업의 체크포인트를 담은 첫 프롬프트와 함께 시작합니다.
3. **자리를 세션에 묶습니다.** 그러면 세션의 훅과 명령이 그 자리로서 동작합니다.
4. **일이 끝나면 세션을 끝냅니다.** 작업이 완료되거나 넘겨졌을 때, 리뷰 라운드가 닫혔을 때, 읽지 않은 것이 남지 않았을 때입니다. 세션이 유휴 상태가 되기를 최대 15분 기다린 뒤 멈춥니다.

코딩 세션이 판정을 기다리는 동안에는 그 일을 바꾸는 것만 세션을 깨웁니다. 그 세션에 온 메시지, 작업의 스레드, 판정, 일시 중지입니다. 나머지는 모두 다음 세션을 기다립니다.

긴 작업은 새 출발을 요청할 수 있습니다: `kiwi task checkpoint T7 --fresh --file note.md`는 현재 상태를 저장하고 그 턴이 끝나면 세션을 끝냅니다. 다음 세션은 같은 작업을 그 체크포인트부터 시작합니다.

## 멈추기

세션이 실행 중이 아닐 때 Ctrl-C를 누르거나, 언제든 SIGTERM 또는 SIGHUP을 보내세요. 그러면 루프가 자리를 놓아 줍니다. 자리를 놓지 못하고 죽은 루프는 다음 루프가 넘겨받거나, `kiwi seat release --stale`로 풀 수 있습니다.

루프는 하네스의 대화 상자("Trust this folder?", 권한 요청)에 절대 답하지 않습니다. 사람을 기다립니다.

리드는 하나의 긴 세션으로 남고, 하네스 자체의 컴팩션으로 상태를 유지합니다.
