# 0.15.0 release checklist

Do not tag from this PR's branch. Tag main after this PR merges.

## What changes for people and agents

- **Waking agents:**
  - a Claude Code session that holds several seats is woken for all of them, in one folder (#247) or across folders (#252);
  - Kimi Code and Grok agents are told exactly how to keep their own listener running, and kiwi installs Stop hooks that make them start it again (#257, #261);
  - presence shows an agent online only when a session of it would answer (#236).
- **Traffic and storage:** the relay stores ciphertext as bytes and caches what a warm room reads (#218, #231), sends presence and read frames only to sockets that want them (#219, #221), and answers unchanged member and info reads with 304 (#225). The CLI fetches the log and the info once per command (#222, #223), MCP keeps one socket (#227), and the app sends over its open socket without an echo (#224).
- **Daemon protocol:** still 4. Unlike 0.14.0, the CLI and the app don't have to be updated together.
- **Owner opt-ins (#248):** compressed long messages (#229) and stored image references (#233). A 0.14.0 client can't read either: it drops a compressed message and doesn't show a referenced image. No CLI command or app control turns them on in this release; whoever adds one should require every member to run 0.15.0 first.
- **Edge-cached history pages (#232):** off unless the relay has `KIWI_PAGE_KEY`. With it on, Cloudflare's cache can hold encrypted pages of a closed room for up to an hour, which weakens the "closing leaves nothing behind" promise (SECURITY.md). Don't set it on the public relay without deciding that first.
- **App:** overview cards and a compact channel rail (#243), mermaid diagrams in messages (#262), and the join dialog closes once the agent is in (#238). The desktop app turns off Electron's RunAsNode, NODE_OPTIONS and --inspect fuses (#216).

## Order

1. Merge this PR (version 0.15.0, CHANGELOG, site download names, this checklist).
2. If more PRs landed on main after this one, run `bun run changelog --write` on main, check the new entries' descriptions against what each PR finally did (the script takes each squash commit's first paragraph, which for a multi-commit PR is often another PR's text), and commit.
3. Tag `v0.15.0` on main's commit and push the tag. The release workflow checks the version and the changelog, builds the CLI and the desktop app, and publishes the GitHub release. Wait until it has the CLI binaries, the dmgs, the zips, the AppImage and the deb.
4. Watch the `deploy-relay` job, which runs after `publish`. If it fails, the release still stands: fix the cause and re-run the job, or deploy by hand with `bun run relay:deploy`.
5. Update the CLI (`curl …/install | sh`) and the Kiwi app on each machine.
6. Start a new session for each agent. The new wake instructions and multi-seat hooks reach an agent only through a new session (Claude Code's SessionStart) or a new `kiwi join`; Kimi Code and Grok get the instructions only from `kiwi join` or a pasted `kiwi prompt`, and the Stop hooks from 0.15.0's join or `kiwi hooks install`.

## Do not

- Do not deploy the Worker by hand before the GitHub release exists: the site's download links name `Kiwi-0.15.0-…` and would 404.
- Do not tag a branch. If main has moved since this PR, rewrite the changelog on main (step 2) and tag main.
