# 0.14.0 release checklist

Do not tag from this PR's branch. Tag main after this PR merges.

## What changes for people and agents

- **Agent names:** an agent that joins without `--as` gets a random handle (`otter-gentle`) and a nickname from what it runs in (#185). The handle is the address; the nickname is what people see.
- **Reviews:** they happen in rounds at a commit, and a verdict judges one round (#176).
- **Daemon protocol 4:**
  - listeners register with the daemon instead of writing pid files (#196); for this one release, an older client's pid files still count;
  - the installers and the app run `kiwi cleanup --quiet`, which removes what older installs left behind.
- **Updates:**
  - a macOS app from this release only installs an update signed by the same Developer ID as itself (#201);
  - a Linux AppImage no longer swaps itself: it shows the update as available, with the release link (#210).

  A 0.13.0 app updating to 0.14.0 still does it the old way, since the check ships inside 0.14.0.
- **Security fixes:** escapes and direction marks are stripped from previews (#187), aliases and copied commands are quoted (#189, #198), and site links open in the person's own browser (#208).
- **The relay deploys with the release** (#207), after the GitHub release exists.

## Order

1. Merge this PR (version 0.14.0, CHANGELOG, site download names, this checklist).
2. If more PRs landed on main after this one, run `bun run changelog --write` on main, check the new entries' descriptions against what each PR finally did (the script takes each squash commit's first paragraph), and commit.
3. Tag `v0.14.0` on main's commit and push the tag. The release workflow checks the version and the changelog, builds the CLI and the desktop app, and publishes the GitHub release. Wait until it has the CLI binaries, the dmgs, the zips, the AppImage and the deb.
4. Watch the `deploy-relay` job. It runs after `publish`, and this is its first run. It needs the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets. If it fails, for example because the token lacks the custom-domain permission, the release still stands: fix the token and re-run the job, or deploy by hand with `bun run relay:deploy`.
5. Update the CLI (`curl …/install | sh`) and the Kiwi app on each machine, both together: the app starts its own daemon, and the daemon protocol is now 4.

## Do not

- Do not deploy the Worker by hand before the GitHub release exists: the site's download links name `Kiwi-0.14.0-…` and would 404.
- Do not tag a branch. If main has moved since this PR, rewrite the changelog on main (step 2) and tag main.
