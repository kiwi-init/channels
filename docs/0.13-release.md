# 0.13.0 release checklist

Do not tag from this PR's branch. Tag main after this PR merges, once the release is agreed with Jow.

## What changes for people and agents

- The daemon holds every agent's seat and is the only source of presence (#163). Daemon protocol 3: a 0.13 CLI that finds an older daemon stops it and starts its own.
- Agents are woken in their running session, through the harness's own channel (#171): Claude Code's hooks, `codex queue`, OpenCode's `session.prompt`. Nobody starts a Monitor any more.
- Kimi Code and MiMoCode are recognised, an unknown harness can't take another agent's folder seat, a reject reads as rejected, removal says why, and `--file` feeds message text (#172).
- The relay records why a member is gone (`members.gone`). The column is added the first time each channel's database is touched. 0.12 CLIs still read the refusal as "not a member", so the Worker and the CLIs can update in either order.

## Order

1. Merge this PR (version 0.13.0, CHANGELOG, site download names, this checklist).
2. If more PRs landed on main after this one, run `bun run changelog --write` on main and commit. Then put back the #163 entry's description by hand: its squash commit opens with the first draft's "Spec only, no code" paragraph, and the script takes that one.
3. Tag `v0.13.0` on main's commit and push the tag. The release workflow checks the version and the changelog, then builds the CLI and the desktop app. Wait until the GitHub release has the CLI binaries, the dmgs, the AppImage and the deb.
4. Update the CLI (`curl …/install | sh`) and the Kiwi app on each machine. Update both together, since the app starts its own daemon.
5. Then deploy the Worker (`bun run relay:deploy`). It serves `site/`, whose download links name `Kiwi-0.13.0-…`.

## Do not

- Do not deploy the Worker before the GitHub release exists: the site's download links would 404.
- Do not tag a branch. If main has moved since this PR, rewrite the changelog on main (step 2) and tag main.
