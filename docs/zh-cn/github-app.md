# GitHub

连接一个仓库后，频道会实时看到它的 PR、issue、检查、推送和工作流运行。中继无法读取频道，也无法在频道中签名，所以它从不自己在频道里发消息：它会把一份精简的通知放进队列，等你的应用下次打开时，由应用签名、加密后发出。

<!-- figure: github -->

## 设置

1. **关联你的账户**。在应用中，设置 → **GitHub** → **关联 GitHub** 会显示一个验证码，并打开 `github.com/login/device`。在那里输入验证码并批准；随后应用会显示*已关联为 @you*。令牌保存在那台电脑上应用的加密存储中，绝不会进入频道或交给智能体。**取消关联**会移除它。
2. **安装 App**。在每个拥有这些仓库的账户或组织上，把 **Kiwi Channels** 安装到这些仓库。
3. 在频道设置的**仓库**下**连接仓库**。你只能连接你关联的账户有推送权限的仓库。

仓库列表变化时，你的应用会在那一次请求中把你的关联令牌发给中继。中继以你的身份询问 GitHub 你能否推送到每个仓库，只要有一个失败就拒绝整个列表，并且不保留令牌的任何部分。只通过你在这件事上信任的中继来连接仓库：记录请求正文的中继可能会留下令牌。

## 中继能看到什么

频道连接了哪些仓库，以及在你的应用取走之前的每个事件：仓库、PR 编号和标题、分支、提交、检查名称和结果，以及操作者。绝不包括正文或 diff。这些 GitHub 本来就都有。排队的通知被取走后即删除，无论如何，超过 7 天或 500 条也会删除。

## 频道已经掌握的内容

GitHub 只发送连接仓库之后发生的事。所以所有者的应用会在打开时、连接仓库时以及每 6 小时，抓取仓库中未关闭的 PR 及其检查、未关闭的 issue，以及最近 30 天内关闭的内容，并且只发布频道还不知道的部分。

当 GitHub 视图为空时，它会说明原因：每个仓库是否安装了 App（未安装时附上安装链接）、它会收到哪些事件，以及最后一次 webhook 是什么时候到的。迁移到组织下的仓库，也需要在那里安装 App。

## 审核与合并

Kiwi 不会在 GitHub 上阻止合并。审核的裁定留在任务的轮次和讨论串里，审核者不会把它抄到 PR 上。合并前要求什么，由仓库自己的规则和 CI 决定。

任务的 `merge` 步骤会在所有者的应用看到 PR 已合并时自行结束。如果 PR 在任务获批之前就已合并，步骤的备注会说明这一点。

成员可以通过中继查看某个提交相对默认分支的 diff，仅限已连接的仓库。

### 如果你的规则仍然要求 `kiwi/review`

Kiwi 过去会为每个频道发布一个检查 `kiwi/review/<频道 ID>`，分支规则可以要求它。这个检查已经停用。只要已连接仓库的规则仍然要求它，所有者的应用就会对那里每个未关闭的 PR 回一个绿色检查“Retired: Kiwi no longer gates merges”，这样就没有东西会等它。在你从规则中移除这项要求之前，`kiwi status` 和任务视图会一直点名这个仓库。Kiwi 读到规则并确认要求已移除后才会停止回应，在此之前不会因为到了某个日期而停止。

## issue 变成任务

`kiwi task add --issue 12` 根据频道仓库中的一个 issue 创建任务，标题沿用 issue 的标题。issue 关闭时，任务也会关闭。只有在所有者开启了*写入 GitHub* 时，任务关闭才会关闭 issue。

## 在你自己的中继上

你自己运行的中继需要一个属于它自己的 GitHub App。步骤见[自托管](self-hosting.md#github)。
