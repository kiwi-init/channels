# タスクごとに 1 セッション

席は 1 つの長いセッションの中にいる必要はありません。`kiwi loop` は席のフォルダーの tmux ウィンドウで動き、作業ごとに新しいハーネスのセッションを始めます。作業が終わるとセッションも終わるので、どのタスクも、席がそれまでにしてきたことをすべて抱えずに、小さく始まります。

<!-- figure: loop -->

```bash
kiwi loop                                         # Claude Code, with its default model
kiwi loop --harness codex --model gpt-6-astra --effort high
kiwi loop --harness kimi                          # inside tmux: Kimi's first prompt is typed in
```

`claude`、`codex`、`grok`、`mimo`、`kimi`、`zcode` を実行できます。

## 何を選ぶか

次の順に選びます。

1. 席が作業中のタスク。
2. 席が担当するレビューのラウンド。
3. 席のほかの未完了のタスク。
4. 判定待ちの自分のタスク。
5. 席宛てのメッセージ。

席が空いていれば、エージェント待ちの承認済みの仕様も引き受けます。リースを取るので、2 つのループが同じ仕様を計画することはありません。

## セッションの進み方

1. **席を押さえます。** ほかの何も席のメッセージを読んだりカーソルを動かしたりしないので、届いたものはセッションを待ちます。
2. **ハーネスを起動します。** クリーンな環境で、作業を示し、終わり方（`kiwi task review T7 --at SHA`、`kiwi task done T7`、判定）を伝え、タスクのチェックポイントを含む最初のプロンプトを渡します。
3. **席を結び付けます。** 席をそのセッションに結び付けるので、セッションのフックとコマンドは席として動きます。
4. **セッションを終えます。** 作業が終わったとき、つまりタスクが完了または引き継がれ、レビューのラウンドが閉じ、未読がなくなったときです。セッションがアイドルになるのを最大 15 分待ってから止めます。

コーディングのセッションが判定を待つ間は、作業に関わるものだけがセッションを起こします。セッション宛てのメッセージ、タスクのスレッド、判定、一時停止です。それ以外は次のセッションを待ちます。

長いタスクは新しく始め直すこともできます: `kiwi task checkpoint T7 --fresh --file note.md` は現在の状況を保存し、そのターンの後でセッションを終えます。次のセッションは同じタスクを、そのチェックポイントから始めます。

## 止め方

セッションが動いていないときに Ctrl-C を押すか、いつでも SIGTERM か SIGHUP を送ります。するとループは席を解放します。席を手放さずに止まったループは、次のループが引き継ぐか、`kiwi seat release --stale` で解放できます。

ループはハーネスのダイアログ（「Trust this folder?」や権限の確認）には決して答えません。あなたを待ちます。

リードは 1 つの長いセッションのまま、ハーネス自身のコンパクションで整えられます。
