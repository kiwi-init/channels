# GitHub

リポジトリを接続すると、チャンネルでそのプルリクエスト、Issue、チェック、プッシュ、ワークフローの実行が、起きたときに見えるようになります。リレーはチャンネルを読むことも、チャンネルで署名することもできないため、自分でチャンネルに投稿することはありません。要点だけにした通知をキューに入れ、次にアプリが開いたときに、アプリが署名・暗号化して投稿します。

<!-- figure: github -->

## 設定する

1. **アカウントを連携します。** アプリで 設定 → **GitHub** → **GitHub と連携** を選ぶと、コードが表示され、`github.com/login/device` が開きます。そこにコードを入力して承認すると、アプリに *@you として連携済み* と表示されます。トークンはそのコンピューターのアプリの暗号化されたストアに保存され、チャンネルにもエージェントにも渡りません。**連携解除**で削除します。
2. **App をインストールします。** リポジトリを持つすべてのアカウントまたは Organization で、そのリポジトリに **Kiwi Channels** をインストールします。
3. **リポジトリを接続します。** チャンネルの設定の**リポジトリ**で行います。接続できるのは、連携したアカウントがプッシュできるリポジトリだけです。

リポジトリの一覧が変わると、アプリはその 1 回のリクエストに限って、あなたの連携トークンをリレーに送ります。リレーはあなたとして、各リポジトリにプッシュできるかを GitHub に問い合わせ、1 つでも失敗すれば一覧全体を拒否し、トークンは何も保存しません。リポジトリの接続は、その点を信頼できるリレーを通してだけ行ってください。リクエストの本文を記録するリレーなら、トークンを保存できてしまいます。

## リレーに見えるもの

チャンネルが接続したリポジトリと、アプリが受け取るまでの各イベントです。リポジトリ、PR の番号とタイトル、ブランチ、コミット、チェックの名前と結果、そして誰が行ったか。本文や差分は決して見えません。いずれも GitHub がすでに持っている情報です。キューの通知は、受け取られた時点で削除されます。受け取られなくても、7 日後または 500 件を超えた時点で削除されます。

## チャンネルにすでにあるもの

GitHub が送るのは、リポジトリを接続した後に起きたことだけです。そのため、オーナーのアプリは、開いたとき、リポジトリが接続されたとき、そして 6 時間ごとに、リポジトリの未完了のプルリクエストとそのチェック、未完了の Issue、過去 30 日間に閉じたものを取得し、チャンネルがまだ知らないものだけを投稿します。

GitHub ビューが空のときは、その理由を表示します。各リポジトリに App がインストールされているか（されていなければインストール用のリンク）、どのイベントを受け取るか、最後の Webhook がいつ届いたかです。Organization に移ったリポジトリには、そこにも App をインストールする必要があります。

## レビューとマージ

Kiwi は GitHub 上のマージを止めません。レビューの判定はタスクのラウンドとスレッドに残り、レビュアーが PR に書き写すことはありません。マージの前に何を必須にするかは、リポジトリ自身のルールと CI が決めます。

タスクの `merge` 手順は、オーナーのアプリが PR のマージを確認すると自動で終わります。PR がタスクの承認より前にマージされていた場合は、手順のメモにそう書かれます。

メンバーは、接続したリポジトリに限り、リレーを通じてコミットのデフォルトブランチとの差分を読めます。

### ルールがまだ `kiwi/review` を必須にしている場合

以前の Kiwi は、チャンネルごとに `kiwi/review/<チャンネル ID>` というチェックを投稿し、ブランチのルールで必須にできました。このチェックは廃止されました。接続したリポジトリのルールがまだ必須にしている間は、オーナーのアプリがそこの開いている PR すべてに緑のチェック「Retired: Kiwi no longer gates merges」で応答するので、何も待たされません。ルールから必須指定を外すまで、`kiwi status` とタスク画面にそのリポジトリ名が表示されます。Kiwi はルールを読んで必須指定がなくなったことを確認すると応答をやめます。それより前に、日付で終わることはありません。

## Issue がタスクになる

`kiwi task add --issue 12` は、チャンネルのリポジトリの Issue から、その名前を付けたタスクを登録します。Issue が閉じるとタスクも閉じます。タスクが閉じると Issue も閉じるのは、オーナーが *GitHub への書き込み* をオンにしている間だけです。

## 自分のリレーでは

自分で動かすリレーには、専用の GitHub App が必要です。手順は[セルフホスティング](self-hosting.md#github)にあります。
