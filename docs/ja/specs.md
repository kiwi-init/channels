# 仕様とタスク

人が依頼します。エージェントがその人と一緒に、それを**仕様**として書き起こします。人が承認すると、最初に手の空いたエージェントが始めます。仕様の範囲内はエージェントが決め、範囲外は人に質問します。

<!-- figure: spec -->

## 仕様

人のメッセージの仕様は Markdown です。目的、範囲に含めるものと含めないもの、まだ残っている質問、そして完了を証明するチェック項目を書きます。

```markdown
# Export the board as CSV

## Done when
- [ ] The Tasks view has an Export button that saves `board.csv`
- [ ] Maya opens it in Numbers and the columns line up
```

- リードか、どのエージェントでも下書きできます: `kiwi spec write 150 --file spec.md`。
- 誰でも編集でき、誰でも仕様の行にコメントできます。アプリでは言葉を選択して、CLI では `kiwi spec comment 150 "…" --on "the line"` で行います。コメントはその人のメッセージのスレッドへの返信なので、エージェントは他のスレッドと同じように読みます。

## 承認

人が、自分の読んだバージョンを承認します。承認できるのは、依頼した人、オーナー、またはオーナーが判断への回答を許可した人です。エージェントは承認できません。承認はそのバージョンを指すので、誰かが読んでいる間に加えられた編集がすり抜けることはありません。

承認後、チェック項目に印を付けるのは進捗です: `kiwi spec tick 150 "columns line up"`。それ以外の編集は変更として扱われ、人には差分で表示されます。新しい作業は人が承認するまで待ちます。すでに始まった作業は続きます。

## 自動で始まる

仕様が承認されると、ほかにやることのない最初のエージェントが引き受けます。席が空いていれば [`kiwi loop`](loop.md) が引き受けます。長いセッションのエージェントは承認で起こされ、`kiwi spec start 150` を実行します。エージェントは仕様をタスクに分け、その人のメッセージの下に登録します（`kiwi task add "…" --ask 150`）。手の空いたエージェントが未完了のタスクを引き受けます。

**承認済みの仕様からのみタスクを作成**（オーナーのスイッチで、アプリで作ったチャンネルではすべてオン）がオンなら、すべてのタスクは承認済みの仕様の一手順です。GitHub の Issue も同じように作業になります: `kiwi task add --ask 150 --issue 12`。

## 段階

段階は誰も入力しません。起きたことに応じて決まります。

| 段階 | いつ |
| --- | --- |
| 下書き | 人が承認するまで |
| 承認済み | エージェント待ち。順番も表示されます |
| 作業中 | 未完了のタスクがある |
| 納品済み | すべてのタスクが完了し、すべての項目にチェックが入った |
| 受け入れ済みまたは取り下げ | 人の判定 |

人はメモを付けて**差し戻す**こともできます。仕様は再びエージェントを待ち、メモが計画するエージェントへの最初の指示になります。取り下げると、未完了のタスクは保留になります。

## タスク

タスクは、未完了、作業中、完了の順に進みます。

```bash
kiwi task add "freeze protocol v1" --ask 150 --start   # file it and take it
kiwi task assign T3 win "edge detection works; multi-monitor next"
kiwi task checkpoint T3 --file note.md                 # where it stands, for the next session
kiwi task done T3
```

`kiwi task start` は、誰も持っていないタスクだけを引き受けます。2 つのエージェントが同時に取りに行くと、一方が取り、もう一方には誰が持っているかが伝えられます。

## アプリでは

**仕様**ビューが作業の中心です。上に「いま」カード、その下に必要なもの別の仕様（あなたの対応待ち、作業中、エージェント待ち、下書き）が並び、それぞれの下に未完了のタスクがあります。仕様を開くと 3 つの部分があります。

- **仕様**: 本文。コメントは引用した行の横の余白に表示されます。
- **内部**: エージェントの作業をひと目で。各タスクとそのプルリクエスト、すべてのメッセージにワンクリックで届きます。
- **結果**: 完了条件、マージされたプルリクエスト、試したこと、そして受け入れる、差し戻す、取り下げる。
